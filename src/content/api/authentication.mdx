---
title: Payment headers
description: How x402 payment headers replace API keys, and how to build and read them with circlekit.
---

An x402 endpoint has no API key. The payment is the credential: a request
carries a signed USDC authorization, and the server accepts the request once
Circle Gateway settles that payment.

## Headers

| Header | Direction | Content |
|--------|-----------|---------|
| `PAYMENT-REQUIRED` | server to client, on `402` | Base64 JSON: the price, network, and `payTo` address |
| `PAYMENT-SIGNATURE` | client to server | Base64 JSON: the buyer's signed authorization, the chosen payment option, and the resource |
| `PAYMENT-RESPONSE` | server to client, on `200` | Base64 JSON: the settlement receipt |

## Build and read them with circlekit

Most clients should call `GatewayClient.pay(url)`, which reads
`PAYMENT-REQUIRED`, signs, and retries with `PAYMENT-SIGNATURE` for you. See
[Pay from a Python agent](/guides/pay-from-an-agent).

To handle the headers yourself:

```python
import httpx
from circlekit import PrivateKeySigner
from circlekit.x402 import create_payment_header, decode_payment_required

signer = PrivateKeySigner("0xYourTestPrivateKey")

first = httpx.get("http://localhost:8000/forecast")
x402 = decode_payment_required(first.headers["payment-required"])

header = create_payment_header(
    signer=signer,
    requirements=x402.get_gateway_option(),
    resource=x402.resource,
)
second = httpx.get("http://localhost:8000/forecast", headers={"PAYMENT-SIGNATURE": header})
```

Always pass `resource`. It is optional in the function signature, but Circle
Gateway rejects a payload without it.

## Signed authorization lifetime

The signed authorization is valid for `maxTimeoutSeconds` from the `402`
response. Circle Gateway currently rejects authorizations shorter than 7
days. circlekit `09828f3` defaults to 4 days, so set a longer window on the
server as shown in the [Quickstart](/quickstart).
